No health endpoint was called: health alone would not prove deployed session/proxy settings.

Source contracts inspected:

- `backend/app.js`: `NODE_ENV=production` controls secure cookies; `TRUST_PROXY_HOPS` defaults to 1 in production, 0 otherwise, and must be a nonnegative integer. Numeric trust is appropriate only when every allowed access path has the expected trusted proxy chain. Actual ingress/direct-origin restrictions remain unknown.
- Session middleware has `proxy: isProduction`, independently trusting forwarded protocol in production; cookie `HttpOnly`, production `Secure`/`SameSite=None`, otherwise non-Secure/`lax`. Default lifetime is 24 hours; override is **SESSION_MAX_AGE_MS**. Local settings contain the different name SESSION_MAX_AGE, which this code does not consume. This is a configuration observation, not a deployment change.
- Credentialed CORS uses exact `CORS_ALLOWED_ORIGINS`, falling back to `CLIENT_URL`; both Axios clients request credentials. Local backend is development with loopback client origin and no explicit proxy-hop override. None of these local values prove Render's environment. `frontend/vercel.json` only rewrites SPA paths; it does not proxy API traffic.
- PostgreSQL `session` storage/15-minute pruning is configured. Real persistence/expiry and cross-site browser cookie acceptance remain untested. Source DB TLS sets `rejectUnauthorized:false` in production and disables SSL in development; this discovery used a separate TLS-verifying connection, not those settings. Record this for a later reviewed configuration/security decision; no fix is included.
- `auth.limits.js` uses process-local MemoryStores, default 15-minute windows: generation 20/IP and 5/email, verification 30/IP and 10/email, reset 30/IP and 5/token. IP bucketing depends on Express proxy trust; multiple workers/restarts do not share/preserve budgets. Direct pharmacy/laboratory registration lacks these auth-router budgets (C3-11 remains open).

```powershell

```

Here `public` is only a placeholder pending catalog confirmation: repeat `--schema` for all required application/dependency schemas.
